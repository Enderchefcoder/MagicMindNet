# DistribAI compatibility

MagicMindNet is compatible with [DistribAI](https://github.com/naxium-oss/DistribAI)
installs — the distributed training control plane that pools contributor GPUs
into orchestrated jobs. On any device running a DistribAI node or orchestrator,
`pip install magicmindnet` drops in cleanly and `magicmindnet.distribai`
bridges the two projects in both directions.

```python
import magicmindnet as ai
from magicmindnet import distribai as bridge

print(bridge.check_compatibility())          # install detection + report

bot = ai.Chatbot(vocab_size=256, n_layer=2, d_model=64, seed=42, final_norm=True)
config = bridge.architecture_config(bot)     # DistribAI architecture_config

client = bridge.DistribAIClient()            # ORCHESTRATOR_ADMIN_URL or 127.0.0.1:8766
client.submit_training_job(bot, dataset=[{"input": "hi", "output": "yo"}], steps=100)
```

Contract mirrored: DistribAI 0.9.0 (`services_python/architecture_config.py`,
`services_python/preflight.py`, `services_python/script_validation.py`,
`worker/src/daemon/script_runner.py`, `worker/src/compute/distribai_models.py`).

## Coexistence

| Requirement | DistribAI | MagicMindNet | Verdict |
|---|---|---|---|
| Python | ≥ 3.11 | ≥ 3.12 | Any 3.12/3.13 interpreter serves both |
| Required deps | torch, grpcio==1.80, protobuf<7, aiohttp, ... | **none** | No pin conflicts possible |
| GPU stack | CUDA primary, CPU fallback | CPU (from-scratch Rust core; optional CUDA feature) | Independent |

`bridge.detect_install()` finds DistribAI four ways: a repo checkout (explicit
path or `DISTRIBAI_HOME`, markers like `proto/distribai.proto`), the installed
`distribai` pip package, a worker node data dir (`~/.distribai`), or a
configured `ORCHESTRATOR_ADMIN_URL`. `bridge.check_compatibility()` wraps that
into a report with the admin URL a client would use.

## Architecture bridge

`architecture_config(bot)` maps a Chatbot onto DistribAI's declarative,
pure-data `architecture_config` (family `decoder_transformer`) and validates
it with a faithful mirror of DistribAI's own bounds (dim 16–4096, layers
1–64/128, heads 1–64, ffn 16–16384, transformer seq_len ≤ 8192, ≤ 512M
estimated params, ...), so bad configs fail locally with DistribAI's message
instead of a 400 from the admin API.

| MagicMindNet | DistribAI | Notes |
|---|---|---|
| `d_model` | `dim` | |
| `n_layer` | `n_unique_layers` | |
| `n_layer * n_loops` | `n_logical_layers` | DistribAI cycles unique layers in the same order MagicMindNet loops its stack |
| `n_heads` / `n_kv_heads` | `n_heads` / `n_kv_heads` | GQA both sides |
| `ffn_dim` | `ffn_dim` | |
| `max_seq_len` | `seq_len` | |
| `attention_window` | `sliding_window` | |

`chatbot_from_architecture(config)` reverses the mapping (only
`decoder_transformer` configs). Features either side cannot represent raise
`ValueError` instead of silently degrading: custom `head_dim`,
prelude/coda layers, `loop_embed`, LoopLoRA, RMSNorm, SwiGLU, and vision on
the MagicMindNet side; nonzero `dropout`, `qk_norm`, `use_head_gating`,
`embedding_scale`, and `attn_res_block_size` on the DistribAI side.

## MyTrainer sync (external/mytrainer)

DistribAI's orchestrator syncs external trainer architectures from
`external/mytrainer/configs/grid_architectures.json`
(`POST /api/admin/mytrainer/sync`). The MagicMindNet repo ships that contract
at its root — `configs/grid_architectures.json` + `models/model.py` — so a
checkout **is** a valid MyTrainer tree:

```bash
# in the DistribAI repo
git clone https://github.com/Enderchefcoder/MagicMindNet external/mytrainer
python scripts/ci/verify_mytrainer_submodule.py --require   # OK
```

The committed profiles (`mmn-tiny` ... `mmn-large`, `mmn-gqa-small`,
`mmn-glint2-mini` with 8× shared-weight loops) are generated by
`bridge.grid_architectures()`; a regression test keeps the file in sync.
`bridge.export_mytrainer_tree(dir)` writes the same tree anywhere (point
`MYTRAINER_PATH` at it), with `extra=` for your own models.

## Script jobs (train MagicMindNet on worker nodes)

`build_script_package()` produces the gzip tarball DistribAI workers execute
(`run.py` + `requirements.txt` + `config.json` + `dataset.json`), pre-checked
against DistribAI's preflight (5 MB cap, `run.py` entry, no secret paths, no
tar traversal/symlinks) and static script rules (no `exec`/`eval`, no
`subprocess`/`ctypes`/`multiprocessing`) — `validate_script_package()` /
`validate_script_source()` expose the mirrors directly.

The default `run.py` (`default_run_py()`) implements the worker contract from
`worker/src/daemon/script_runner.py`:

| Worker side | Script side |
|---|---|
| writes `hyperparams.json` | reads epochs / lr / batch_size / vocab_size / seed / `architecture_config` |
| sets `DISTRIBAI_TASK_ID` / `DISTRIBAI_JOB_ID` / `DISTRIBAI_JOB_TYPE` | echoed into `results.json` |
| installs `requirements.txt` into `.site-packages` | `magicmindnet>=0.2.1` |
| collects `results.json` / `metrics.json` | loss history + final loss |
| flags `checkpoint.pt` | DistribAI-native state dict (below) |

## Job submission

`DistribAIClient` speaks the orchestrator admin HTTP API with stdlib-only
HTTP, following the `distribai` CLI conventions (`ORCHESTRATOR_ADMIN_URL`,
Bearer `DISTRIBAI_ADMIN_SECRET`):

| Method | Route |
|---|---|
| `health()` / `stats()` / `nodes()` / `jobs()` / `job(id)` | `GET /admin/...` |
| `submit_job(...)` | `POST /admin/jobs` (validated `architecture_config`, base64 script package + pinned `package_sha256`) |
| `cancel_job(id)` / `retry_job(id)` | `DELETE /admin/jobs/{id}` / `POST .../retry` |
| `submit_training_job(bot, dataset=...)` | one call: map config, build package, submit |

Orchestrator errors surface as `DistribAIError` with the server's message.

## Checkpoint interop

`export_checkpoint(bot, path)` writes DistribAI's native `state_dict` names —
`.pt` (torch.load-compatible zip, written from scratch) or `.safetensors`
(their `export_safetensors` layout). `import_checkpoint(path)` reads flat
state dicts, safetensors, **and** the nested
`torch.save({"model_state": ..., "config": ..., "step": ...})` wrapper
`DistribAIModelWrapper.save_checkpoint` produces. Neither direction needs
torch installed.

| DistribAI tensor | MagicMindNet tensor |
|---|---|
| `model.embedding.weight` | `embed` |
| `model.position_embedding.weight` | `pos_embed` (learned) / synthesized sinusoidal table on export |
| `model.layers.N.self_attn.in_proj_weight` | fused ⇄ split `blocks.N.attn.{q,k,v}` |
| `model.layers.N.self_attn.out_proj.weight` | `blocks.N.attn.out` |
| `model.layers.N.q_proj/k_proj/v_proj/o_proj.weight` (GQA block) | `blocks.N.attn.{q,k,v,out}` |
| `model.layers.N.linear1/linear2.weight` (or `ffn.0`/`ffn.3`) | `blocks.N.ffn` / `blocks.N.ffn2` |
| `model.layers.N.norm1/norm2.{weight,bias}` | `blocks.N.ln1/ln2.{gamma,beta}` |
| `model.norm.{weight,bias}` | `final_norm.{gamma,beta}` |
| `model.fc_out.weight` | `lm_head` |

Fidelity notes:

- DistribAI's decoder always ends in a LayerNorm, so build bots with
  `final_norm=True` for exact roundtrips (`import_checkpoint` always sets it).
- Torch-only biases (attention / FFN / `fc_out`) export as zeros and are
  dropped on import — MagicMindNet blocks are bias-free.
- Torch checkpoints don't record head count or loop count: pass `n_heads=`
  (default 4, falling back to 1 like `DistribAITinyLanguageModel`) and
  `n_loops=` (from the job's `architecture_config`) on import.
- Tensor-level mapping: DistribAI's stock blocks are post-norm GELU while
  MagicMindNet blocks are its own layout, so cross-framework *forward* passes
  are architecture-equivalent only where those semantics line up.

`ai.load_pt` / `ai.load_arrays` gained nested-dict flattening with dotted
names (`model_state.model.embedding.weight`), so any wrapper checkpoint —
DistribAI, Lightning-style, custom — surfaces its tensors without torch.

## Cross-validation

Beyond the offline suite (`tests/test_distribai_*.py`), the bridge was
validated hands-on against DistribAI's actual code with real torch:

- every grid profile passes DistribAI's `validate_architecture_config` and
  builds + forwards via their `get_model()`;
- our exports load into `DistribAIModelWrapper` with `load_state_dict(strict=True)`
  (both MHA-fused and GQA naming);
- their `save_checkpoint` / `export_safetensors` outputs import back with
  weight equality, full circle mmn → DistribAI → mmn preserving loss;
- our packages pass their `validate_script_tarball` + `validate_submitted_script`;
- a MagicMindNet checkout at `external/mytrainer` passes
  `verify_mytrainer_submodule.py --require` and `MyTrainerSync.sync()`
  registers the profiles.
